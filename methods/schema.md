# 数据标注规范(Schema)v0.5

> 本文件是平台无关层的核心:任何工具上重建本数据库,以此为准。校验脚本 `validate_entries.py` 是「校验规则」列的机器实现。

| 序 | 字段名 | 字段ID | 必填 | 类型 | 取值约束 | 校验规则 | 填写说明 |
|---|---|---|---|---|---|---|---|
| 1 | 条目ID | entry_id | 是 | 文本 | S##-### | 正则 ^S\d{2}-\d{3}$;全库唯一 | 学生编号+三位序号,如 S07-013。由录入人自行编号,组内不得重复。 |
| 2 | 文件名称 | doc_title | 是 | 文本 | 规范全称 | 非空;不得用简称 | 必须写全称。机器无法把简称与全称对齐。 |
| 3 | 文号 | doc_number | 条件必填 | 文本 | 〔〕六角括号;法律可不填 | 法律位阶:可空或填「无文号」;其余位阶:非空且含年份 | 法律用主席令号或不填;确无文号的文件明确写「无文号」,以区别于漏填。注意是〔〕不是[]。 |
| 4 | 位阶 | hierarchy | 是 | 枚举 | 法律/行政法规/部门规章/地方立法/规范性文件/政策文件 | 必须∈六个枚举值 | 「地方立法」涵盖地方性法规与地方政府规章,录入时在备注注明具体类型。 |
| 5 | 制定区域 | region | 是 | 枚举 | 国家/11沿海省市 | 必须∈十二个枚举值;区域与位阶匹配(地方立法不得填「国家」,法律/行政法规/部门规章不得填省市) | 国家层条目填「国家」。地方层条目填省市名——这是央地比对的筛选键。 |
| 5 | 发布机关/牵头机关 | issuer | 是 | 枚举+自由 | 见受控词表 | 须与位阶匹配(如部门规章不得由省政府发布) | 联合发文取牵头机关,其余机关写入备注。机构改革后的名称变化要注明。 |
| 6 | 公布日期 | promulgate_date | 是 | 日期 | YYYY-MM-DD | 日期格式;不晚于施行日期 | 公布与施行常常不是同一天,分开记录。 |
| 7 | 施行日期 | effective_date | 是 | 日期 | YYYY-MM-DD | 日期格式 | 以文件本身载明的施行日为准。 |
| 8 | 效力状态 | status | 是 | 枚举 | 现行有效/已修订/已废止/尚未生效 | 必须∈枚举;与失效日期逻辑一致 | 「已修订」指本文本已被新版取代,必须在备注注明现行版本。 |
| 9 | 失效或修订日期 | end_date | 条件必填 | 日期 | YYYY-MM-DD | 状态非「现行有效」时必填;须晚于施行日期 | 这是数据库最容易自相矛盾的地方,务必与状态列对照检查。 |
| 10 | 主题标签(主) | topic_main | 是 | 枚举 | 九类,见受控词表标签定义表 | 必须∈九个枚举值 | 对应领域地图九类。一条数据只能有一个主标签。规范级标签是粗定位,条目级标签才是检索主力:同一部法律的不同条文可以打不同标签。 |
| 11 | 主题标签(次) | topic_sub | 否 | 枚举 | 九类,见受控词表标签定义表 | ∈枚举或空;不得与主标签相同 | 跨主题条款用次标签补充,便于交叉检索。 |
| 12 | 条文定位 | provision_ref | 是 | 文本 | 第X条第X款第X项 / 第X段 / 第X项((一)(二)连续编号,政策文件) | 含「条」「段」或「项」;法条须精确到款项;政策文件按部分+自然段或(一)(二)项编号定位 | 法律法规精确到款、项;政策文件无条款结构的,按「第X部分第X段」定位。定位不精确,机器无法回溯核对。政策文件业务性部分的(一)(二)…连续编号按「项」处理(仅限政策文件)。同一款/段内可用「第X句」细分。 |
| 13 | 规范主体 | norm_subject | 是 | 文本 | ≤30字 | 非空 | 谁?——权利义务的承受者。指导性规范的对象往往较抽象,如实记录并在备注说明。条文未明示主体时,结合章节归属、上下文条文与权威资料推断,并在备注注明推断依据。 |
| 14 | 适用条件 | norm_condition | 是 | 文本 | ≤80字 | 非空 | 在什么情况下?——假定条件。若条文无明示条件,写「一般情形」。 |
| 15 | 行为模式类型 | norm_type | 是 | 枚举 | 义务性/授权性/禁止性/定义性/程序性/指导性/惩罚性 | 必须∈七个枚举值 | 「应当」→义务性,「可以」→授权性,「不得/禁止」→禁止性。「指导性」:应当、可以等的对象较为抽象,不指向具体行为,不具备直接执行可能,可解释空间大——经济公法中大量存在,其功能是指明方向、维系并化解不确定性、为经济活动留下创造空间(多见于政策文件与规划)。「惩罚性」:法律责任章中对违法行为设定制裁的规范(违反X的,由Y处Z)——中国立法惯例将法律责任单列一章,此类条文单独标注,法律后果字段填制裁具体内容。 |
| 16 | 行为模式内容 | norm_behavior | 是 | 文本 | ≤120字 | 非空;须含行为动词 | 必须/可以/禁止/倡导做什么?——用自己的话概括,不得整段复制原文。 |
| 17 | 法律后果 | norm_consequence | 否 | 文本 | ≤80字 | 可空(定义性、指导性条款常无) | 违反或符合时如何?——罚则、许可、失权等。本条无载明的写「本条未设」。指导性规范通常无强制后果,这正是其特征。 |
| 18 | 原文摘录 | source_text | 是 | 长文本 | ≤200字 | 非空;字数上限;与行为模式内容相似度<0.8 | 仅供核对用,不进入检索主字段。超过200字说明你选的条文太大,应当拆分。 |
| 19 | 关联条目 | related_ids | 否 | 文本 | 逗号分隔的条目ID | 每个ID须在全库中存在 | 上位法与实施细则、原则条款与罚则条款之间建立关联。注意与规范清单的「关联规范」(文件级)区分:这里是条目级关联。 |
| 20 | 央地权限配置 | central_local_config | 条件必填 | 枚举 | 统一执行/授权细化/因地制宜/未作规定/中央专属 | 制定区域=国家 时必填;地方条目留空 | 本条中央规范给地方留下什么空间?统一执行=全国一体适用、地方无裁量;授权细化=明确授权地方作出具体规定(如「具体办法由省级人民政府制定」);因地制宜=允许地方选择幅度、方式、时点,含试点授权;未作规定=对地方权限沉默;中央专属=事项明示或依性质专属中央(如领海、专属经济区)。 |
| 21 | 地方自主权类型 | local_autonomy_type | 条件必填 | 枚举 | 执行性/细化性/创设性/可协商性/无权限(存疑) | 制定区域≠国家 时必填;国家条目留空 | 本条地方规范相对中央权限的性质:执行性=重述或直接执行上位规范,无实质新增;细化性=在上位授权或框架内具体化标准、程序、幅度;创设性=对上位法未规定事项先行创制;可协商性=基于央地协商机制形成(试点批复、部省协议等);无权限(存疑)=涉及事项疑属中央专属或缺乏上位依据——如实记录并写明理由,这是标记疑点供课堂讨论,不是宣告违法。 |
| 22 | 核实来源 | source_db | 是 | 枚举 | 见受控词表 | 必须∈枚举 | 注明你在哪个权威库核对过原文。AI 检索结果不得作为来源。 |
| 23 | 录入人 | author | 是 | 文本 | 学号+姓名 | 非空;与条目ID前缀一致 | 用于评分与溯源。双人录入的规范,两人各自独立成表,不合并署名。 |
| 24 | 版本 | version | 是 | 枚举 | v1/v2/定稿 | 必须∈枚举 | v1 为首轮提交,v2 为校验反馈后的修订稿。 |
| 25 | 录入日期 | entry_date | 是 | 日期 | YYYY-MM-DD | 日期格式 |  |
| 26 | 备注 | remark | 否 | 文本 |  |  | 版本变化、机构沿革、地方立法具体类型、存疑之处写在这里。存疑不是扣分项,隐瞒才是。 |
